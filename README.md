# Content Workflow Guardrails

Small, local Python controls for an AI-assisted editorial workflow.

**A draft being approved is not the same thing as a post being published. A reminder being possible is not a reason to send it again.**

This tool makes a few of those rules explicit. It evaluates reminder/pause recommendations and counts unique posting days without double-counting platforms.

It does not write posts, contact anyone, call an API, scrape a feed, update a queue, or publish content.

## Why this exists

An AI-assisted content workflow needs more than good copy. It needs to remember when a draft has already been shown, distinguish approval from publication, and avoid treating missing evidence as proof that nothing happened.

These controls were extracted from a real editorial workflow and developed with AI assistance. The public examples and tests use synthetic records, not business/customer data. This is a small, inspectable utility—not a claim that AI can manage a brand autonomously.

## Quick start

Requires Python 3.9+ and IANA timezone data for `Asia/Bangkok`. No third-party Python runtime packages are needed on systems with that timezone data.

From the repository root:

```bash
python3 scripts/workflow-controls.py evaluate \
  --input examples/drafts.json --as-of 2026-10-03

python3 scripts/workflow-controls.py weekly \
  --input examples/publications.json --start 2026-10-05 --end 2026-10-11

python3 -m unittest discover -s tests -v
```

If your Python installation does not have IANA timezone data (common on Windows), install `tzdata` in your own environment before running. The current calendar timezone is deliberately **Asia/Bangkok**, not an inferred machine timezone. It is not configurable via a CLI flag in this version.

## What it does

### Evaluate recommendation state

- Applies a shared cap of two presentations of unchanged copy: initial delivery plus one reminder.
- Recommends a pause after seven calendar days without a later item-specific reply, where a user decision is actually pending.
- Respects a future agreed review and work already authorised for production.
- Retains existing paused/closed suppression; it does not automatically resume work.
- Closes active/cooldown recommendations when publication has already been reported or verified.
- Preserves the supplied content status, copy approval, publication evidence and custom fields. It updates recommendation/control fields in the returned JSON only.

The cap relies on the caller supplying a correct **cross-channel presentation count**. The tool does not collect or reconcile deliveries for you. A returned cooldown/pause is advice for an orchestrator; this script cannot enforce another agent's behaviour.

### Count posting days

- Deduplicates stable event IDs within each platform/account.
- Reports verified days separately from additional user-reported-only days.
- Counts a day once in the all-channel union even if several platforms have posts.
- Keeps unknown-date records unassigned, rather than assigning them to today or this week.
- Rejects conflicting dates for the same event.
- Does not infer feed coverage, engagement, sales or a healthy marketing funnel.

## Try the examples

All example data is **synthetic**. For the evaluate command above, the expected recommendation states are `cooldown`, `paused`, and `closed`. The approval and publication fields are retained.

The weekly example has verified posts on two platforms on the same Bangkok day. Its all-channel union is one dated day, plus one unknown-date report that is not assigned to the week.

The `examples/expected-*.json` files are generated by actually running these commands. They are not live analytics or fabricated API responses.

## Input contract and policy details

See [docs/input-contract.md](docs/input-contract.md). Input is a JSON array of records. Dates should be ISO-8601; date-only and timezone-naive inputs are interpreted in Bangkok time, while offset-bearing timestamps are converted to it.

Unknown fields are passed through. **This is not a redaction tool.** Do not put secrets in input metadata and then assume the output is safe to publish.

## Verification

Run the test command above. The suite covers pause boundaries, later replies, shared reminder caps, production exemptions, preservation of approval/publication state, timezones, event deduplication and invalid boolean reminder counts.

Local test/demo evidence is recorded in [docs/verification.json](docs/verification.json). GitHub CI has not been run or claimed; no remote repository is created by this package.

## Limits

- It trusts supplied records; it cannot verify a publication or authenticate an approval.
- It does not assess writing quality, factual claims, medical safety, licensing or permission to publish.
- An explicit resume must be handled by the calling workflow. Do not reset reminder counts just to evade the cap.
- The calendar policy is a design choice, not an empirically proven optimal posting schedule.
- Invalid input exits nonzero; this small CLI uses standard Python exceptions rather than a structured error API.
